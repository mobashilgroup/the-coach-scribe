# The Coach Scribe

AI documentation assistant for coaches: turn a coaching conversation into a
structured, reviewable, shareable record — recording → transcription →
diarization → structured AI summary → **coach review & approval** → history →
export/share. Nothing generated by AI is shared without explicit human approval.

*A product of Mobashil Group S.A.* This repository is the production monorepo,
rebuilt from the master specification in [`docs/product/master-spec.md`](docs/product/master-spec.md).
It replaces the earlier PWA prototype, which is preserved for reference only
under [`legacy/pwa-prototype/`](legacy/pwa-prototype/) and must **not** be reused
architecturally (Spec §32).

## Status — Milestone 1: Backend API core ✅

The load-bearing backend that every other surface depends on is implemented and
tested end-to-end. Delivered:

- **`services/api`** — Node + TypeScript + Fastify + Prisma (PostgreSQL).
- Full data model (Spec §16) with strict organization / coach isolation.
- Pure, unit-tested domain logic: configurable **plans engine**, session
  **state machine**, **usage** accounting, **AI summary schema + repair**,
  **consent** gating, **retention** scheduling.
- Transcription (Deepgram) and analysis (OpenAI) behind **swappable provider
  interfaces**, with deterministic fakes so the whole flow runs with no keys.
- REST endpoints for auth, clients, sessions (+consent, process, retry),
  transcript/summary (+approve, share), tasks, goals.
- **51 passing tests**, including a live-database E2E covering the mandatory
  flow and cross-tenant isolation.

Since then the workflow has been completed and **verified end to end in a real
browser** through a functional coach web console (`apps/web_portal`):

```
register → add client → new session (free text OR audio upload)
        → recording consent → process (transcribe + diarize + AI summary)
        → review & edit → approve → share → history → export (JSON / HTML)
```

- **Resumable chunked upload** + storage interface (Spec §10.14, §15.1).
- **Export**: JSON + branded printable HTML (Spec §10.22).
- **Coach web console** — black/white/gold, no build step, no fake buttons;
  every action hits the real API. Screenshots of the verified run live in
  [`apps/web_portal/verification/`](apps/web_portal/verification/).
- **58 passing tests** (unit + live-DB E2E incl. the audio recording path).

### Fase 2 — client portal + messaging (also browser-verified)
The continuous-relationship loop (Spec §8.4, §11) is built and verified:

```
coach shares → invites client (magic link) → client opens portal
   → sees ONLY shared sections → updates a task → sends an urgent note
   → AI drafts a reply from minimized context → coach edits & sends
   → client sees the reply        (nothing is ever sent automatically)
```

- Single-use magic-link portal access; client tokens rejected on coach endpoints.
- Sharing persists the exact selected sections; transcript/private notes never exposed.
- AI reply drafts from **minimized** context (transcript/quotes/emotions stripped).
- In-app notifications; coach Messages UI + standalone `portal.html`.
- Verified in Chromium (`apps/web_portal/verification/verify-portal.mjs`).

### Mobile app (Flutter) — scaffolded, device-verification pending

## Quick start

See [`docs/deployment/local.md`](docs/deployment/local.md). In short:

```bash
pnpm install
docker compose up -d postgres
cd services/api && pnpm prisma:generate && pnpm prisma:migrate && pnpm exec tsx prisma/seed.ts
pnpm dev        # http://localhost:4000/health
```

## Security note
The legacy `config.js` committed Google and PayPal client IDs into a frontend
bundle. Treat those as compromised and rotate them. In this codebase, secrets
live only in the API tier and are validated at boot; nothing sensitive is ever
bundled into a client.
